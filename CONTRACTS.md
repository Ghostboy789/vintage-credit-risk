# Contracts

The exact interfaces between the parts of this project: the dbt marts, the model-output files,
the metrics layer and the published JSON artefacts. Everything that produces one of these must
match it exactly, and everything that reads one may rely on it.

- **Machine-readable form**: `tests/contracts.py` holds the same specs and a checker. A test
  keeps this file and that module in step, so a column cannot be added to one without the other.
- **Checking an output**: `check_mart(name, path)`, `check_model_output(name, path)` and
  `check_artefact(name, obj_or_path)` in `tests/contracts.py` return a list of problems. An
  empty list means the output follows the contract. Import it from the repo root as
  `from tests import contracts`.
- **Examples**: `tests/fixtures/` holds a small **synthetic** example of every file below,
  generated by `scripts/make_fixtures.py`. The fixtures are made up and must never reach a
  dashboard, README or published artefact (see "Synthetic fixtures" at the end).
- **Definitions** (default, cure, exposure, LGD, stages and so on) are in `VALIDATION_PLAN.md`.
  Rule IDs such as D1 or E1 refer to that file. This file says where each definition lives,
  not why.
- **Changing a contract** means editing this file, `tests/contracts.py` and the fixtures
  together, in one commit, and telling every reader of the changed file.
- **Publication** (VALIDATION_PLAN section 12): the marts and model outputs are loan-level and
  are never committed or published. Only the artefacts, and data files built from them, are
  published: aggregates only, no loan identifier, and no cell describing fewer than 10 loans
  (see "Small cells" under the artefact rules). Non-commercial; Freddie Mac is credited as the
  source wherever results are shown.

## Conventions

| Topic | Rule |
|---|---|
| Types | `string`, `int` (any Parquet integer), `float` (Parquet double), `bool`, `date` (Parquet `date32`) |
| Months | Every date is the first day of its month. `period` is the reporting month. |
| Data cut-off | 2026-03-01, the last reporting month in the data |
| Money | US dollars, as reported, not rounded |
| Freddie Mac percentages | Kept in source units and named `_pct`: `ltv_pct` 80 means 80%, `note_rate_pct` 6.5 means 6.5% |
| Model rates | PD, LGD, default and loss rates, shares and coverage are fractions: 0.0123 means 1.23% |
| Missing values | Freddie Mac sentinel codes (FICO 9999; DTI, LTV, CLTV, MI and ELTV 999; categorical `9` or `99`) become null. No sentinel number ever reaches a mart. |
| Zero Balance Codes | Integers: 1, 2, 3, 9, 15, 16, 96 |
| Vintage | The loan's origination year, taken from the loan identifier (`PYYQn...`, so `F07Q3...` is 2007 Q3). This is also the sample file year. |
| Files | Marts go to `marts_out/<name>.parquet` and model outputs to `models_out/<name>.parquet`, both under `VINTAGE_DATA_ROOT` (never committed). Artefacts go to `artefacts/<name>.json`. |
| Keys | The key columns listed for each file are unique and never null |
| Portability | The dbt models build unchanged on BigQuery and on DuckDB. Medians and hashes, which differ by warehouse, sit in one macro each. |

Shared value sets (enums):

| Name | Values |
|---|---|
| dpd bucket (D9) | `current`, `dpd_30`, `dpd_60`, `dpd_90p`, `reo`, `unknown` |
| SMA class (D9) | `standard_or_sma_0`, `sma_1`, `sma_2`, `npa`, `unknown` |
| exit type (D5) | `prepaid`, `matured`, `credit_event`, `other_exit` (null while the loan is active) |
| age band (L1) | `pre` (months on book 0 or less), `1_12`, `13_24`, `25_36`, `37_60`, `61_120`, `121p` |
| LTV band (G1) | `le_60`, `60_80`, `80_90`, `90_95`, `gt_95`, `missing` (upper bound inclusive: 80 is `60_80`) |
| FICO band | `lt_620`, `620_659`, `660_699`, `700_739`, `740_779`, `ge_780`, `missing` |
| term band | `le_180`, `181_240`, `gt_240` months |
| economic period | `pre_crisis` to 2006-12, `crisis` 2007-01 to 2011-12, `recovery` 2012-01 to 2020-02, `covid` 2020-03 to 2021-12, `recent` from 2022-01 |
| grade | `A` to `G` on the PD master scale (VALIDATION_PLAN section 3) |

### `dim_date`
One row per calendar month from 1999-01 to the data cut-off. Key: `month`.

### `fct_loss_events`
One row per resolved primary default: `resolution` in (`credit_event_loss`, `paid_off`). This
is the LGD sample frame (D8); `defect_settlement`, `other_exit`, `cured_active` and `open`
defaults are not in it. Key: `loan_id`. Loss components are signed as Freddie Mac
discloses them (recoveries negative, expenses positive) and are 0 where absent.

| Column | Type | Null | Meaning |
|---|---|---|---|
| `loan_id` | string | no | |
| `vintage_year` | int | no | |
| `default_period` | date | no | From `fct_default_events` (primary) |
| `disposition_period` | date | no | `resolution_period` from `fct_default_events` (the Zero Balance Effective Date's month) |
| `months_to_resolution` | int | no | Months from `default_period` to `disposition_period` |
| `zero_balance_code` | int | no | 1, 2, 3, 9 or 15 |
| `disposition_type` | string | no | `third_party_sale` (2), `short_sale_chargeoff` (3), `reo_disposition` (9), `whole_loan_sale` (15), `paid_off` (1) |
| `ltv_band` | string | no | From `dim_loan` |
| `property_state` | string | no | From `dim_loan` |
| `note_rate_pct` | float | no | Original note rate (discount rate) |
| `ead` | float | no | From `fct_default_events` |
| `removal_upb` | float | no | Zero Balance Removal UPB |
| `net_sales_proceeds` | float | no | Parsed to a number from the raw text field |
| `mi_recoveries` | float | no | |
| `non_mi_recoveries` | float | no | |
| `legal_costs` | float | no | |
| `maintenance_and_preservation_costs` | float | no | |
| `taxes_and_insurance` | float | no | |
| `miscellaneous_expenses` | float | no | |
| `total_expenses` | float | no | As reported (R6 checks it against the four components) |
| `delinquent_accrued_interest` | float | no | |
| `freddie_actual_loss` | float | yes | Freddie Mac's `actual_loss` as reported; null for `paid_off` |
| `computed_loss` | float | no | `removal_upb + net_sales_proceeds + delinquent_accrued_interest + total_expenses + mi_recoveries + non_mi_recoveries`; 0 for `paid_off` (R5 checks it against `freddie_actual_loss`) |
| `net_recovery` | float | no | `-(net_sales_proceeds + mi_recoveries + non_mi_recoveries + total_expenses)`; equal to `ead` for `paid_off` |
| `discount_factor` | float | no | `(1 + note_rate_pct / 1200) ^ -months_to_resolution` |
| `lgd_economic` | float | no | `(ead - net_recovery * discount_factor) / ead`; 0 by definition for `paid_off` (not the formula, D8). Primary LGD |
| `lgd_undiscounted` | float | no | `computed_loss / ead`; 0 by definition for `paid_off` |
| `lgd_gross_of_mi` | float | no | As `lgd_economic`, with `mi_recoveries` removed from `net_recovery`; 0 by definition for `paid_off` |
| `in_lgd_sample` | bool | no | `default_period` at least 36 months before the data cut-off (D8) |

### `fct_roll_rates`
Month-to-month transitions. One row per from-month, vintage, from-bucket, forbearance flag and
to-state that occurs. Key: `period`, `vintage_year`, `from_bucket`, `from_forbearance`,

| `upb` | float | no | Sum of `current_upb` in the from-month |

| `roll_rate` | float | no | `n_loans / n_from`. Rates over `to_state` sum to 1 per from-cell |

A roll-rate cure (D4) is `from_bucket` in (`dpd_30`, `dpd_60`, `dpd_90p`) with `to_state` =
`current`.

## Metrics layer (MetricFlow)

Semantic models sit on `fct_loan_month` (time dimension `period`), `fct_loss_events` (time
dimension `disposition_period`) and `fct_ecl` (time dimension `reporting_date`). Each metric
must equal the matching `metrics_monthly` column, or the stated `fct_ecl` aggregate, for every
month (R7).

| Metric | Type | Measure(s) | Filter | Definition | Equals |
|---|---|---|---|---|---|
| `active_loans` | simple | count of `fct_loan_month` rows | `zero_balance_code` is null | Active loan-months at month end | `n_active_loans` |
| `total_upb` | simple | sum of `current_upb` | `zero_balance_code` is null | Balance of active loans | `total_upb` |
| `delinquency_rate_30p` | ratio | sum of `current_upb` where `dpd_bucket` in (`dpd_30`, `dpd_60`, `dpd_90p`, `reo`) over `total_upb` | active | UPB-weighted share of active balance 30 or more days past due, including REO acquisition, as reported (not adjusted for forbearance) | `delinquency_rate_30p` |
| `delinquency_rate_90p` | ratio | sum of `current_upb` where `dpd_bucket` in (`dpd_90p`, `reo`) over `total_upb` | active | UPB-weighted share of active balance 90 or more days past due, including REO acquisition, as reported | `delinquency_rate_90p` |
| `default_rate` | ratio | count where `is_first_default_month` over count where `at_risk_at_start` | none | Monthly rate of first defaults (primary definition D1, first occurrence) among loans at risk of a first default at the start of the month (active, and no earlier primary default) | `default_rate` |
| `loss_rate` | ratio | sum of `fct_loss_events.computed_loss` over `total_upb` | `disposition_type` is not `paid_off` | Monthly realised net loss (Freddie Mac actual-loss formula, net of MI and all recoveries, undiscounted, dated at disposition) over active balance | `loss_rate` |
| `ecl_total` | simple | sum of `fct_ecl.ecl` | `scenario = 'final'` | Published ECL | sum of `ecl` by `reporting_date` |
| `coverage_ratio` | ratio | sum of `ecl` over sum of `ead` | `scenario = 'final'` | ECL as a share of exposure | `sum(ecl) / sum(ead)` by `reporting_date` |

`ecl_total` and `coverage_ratio` can only be built on the real warehouse after the ECL engine
has written `ecl_results`. Until then they run in CI on the fixture only.

## Published JSON artefacts (`artefacts/`)

### Common rules

Every artefact is one JSON object with these envelope fields first:

| Field | Type | Meaning |
|---|---|---|
| `schema_version` | string | `"1.0"` |
| `artefact` | string | The file's name without `.json` |
| `synthetic` | bool | `true` only for fixtures. Real outputs are `false`, and anything that displays artefacts must refuse or visibly flag `true` |
| `generated_at` | string | ISO 8601 UTC timestamp |
| `data_cutoff` | date string | `"2026-03-01"` |
| `code_version` | string | Git commit of the code that produced it |
| `suppressed_cells` | int | Cells suppressed under the small-cell rule below (metrics nulled plus list rows removed); 0 if none |

Every published number is a **metric object**:

```json
{"value": 0.0123, "ci_low": 0.0101, "ci_high": 0.0148, "n": 48211, "ci_method": "wilson_95"}
```

- `value`: number, or null if it could not be computed.
- `ci_low`, `ci_high`: the 95% interval, both set or both null. If set, `ci_low <= value <= ci_high`.
- `n`: the number of observations behind the value (loans, loan-months or defaults, as the
  field says).
- `ci_method`: how the interval was made, using the methods fixed in VALIDATION_PLAN section 4
  (`wilson_95`, `wilson_95_loan_months`, `jeffreys_95`, `bootstrap_1000`,
  `paired_bootstrap_1000`, `jeffreys_95_over_mean_pd`, `parameter_draws_1000`, `t_interval_years`
  and so on). With no interval it starts with `none:` and gives the reason, for example
  `none: population count, not an estimate`.

**Small cells** (VALIDATION_PLAN section 12). No published value may describe fewer than 10
loans. The checker enforces it on every metric's `n` and on every integer field named `n`,
`n_loans` or `n_defaults`: each must be 0 or at least 10. A producer either merges small
segments before writing (and says so in the evidence text or the field's documentation), or
calls `contracts.suppress_small_cells(artefact)`. That replaces a metric with fewer than 10
loans by `{"value": null, "ci_low": null, "ci_high": null, "n": 0, "ci_method": "none:
suppressed, fewer than 10 loans"}`, removes list rows whose `n`, `n_loans` or `n_defaults` is
below 10, and returns the number of cells it suppressed, which goes in `suppressed_cells`. A
metric's `n` counts loans; where it counts loan-months or defaults, the producer must still
make sure the cell covers at least 10 distinct loans.

Dates inside artefacts are `YYYY-MM-DD` strings. Keys are exact: the checker rejects missing
and unexpected keys. Lists may be empty. `pass_rules` entries are
`{"rule_id", "result", "evidence"}`, with `result` one of `PASS`, `FAIL`, `AMBER`,
`INSUFFICIENT`, `NOT_RUN`, `pending`, and the rule IDs from `VALIDATION_PLAN.md`.

The fixtures in `tests/fixtures/artefacts/` are the full worked examples. The snippets below are
shortened.

## Synthetic fixtures

`scripts/make_fixtures.py` writes, with a fixed seed:

| Path | What |
|---|---|
| `tests/fixtures/raw/sample_orig_YYYY.txt`, `sample_perf_YYYY.txt` | Raw pipe-delimited files in the official 31 and 35 field layout, for 4 vintages (2005, 2007, 2019, 2022), including REO, short sale, defect settlement, forbearance, deferral, modification, `XX` and code 16/96 cases. The extractor turns them into Parquet; the dbt CI build runs on that |
| `tests/fixtures/marts/<mart>.parquet` | Every mart above |
| `tests/fixtures/models_out/<name>.parquet` | `loan_scores`, `ecl_results` |
| `tests/fixtures/artefacts/<name>.json` | Every artefact above |

Every value is simulated. None is copied from, or fitted to, the Freddie Mac data. The fixtures
are marked three ways so that they cannot pass for real outputs: Parquet file metadata
`synthetic = true`, `"synthetic": true` in every JSON artefact, and an `S` as the sixth
character of every loan identifier (`F07Q1S000123`), which no real identifier has. The marts are
derived from one simulated panel, so they agree with each other and with the raw files. They are
still a fixture, not a reference implementation: the dbt project is the only real
implementation of the definitions.
